# WHY / HOW / WHAT

## WHY

People should be able to rely on software doing what was actually intended, even when implementation happens faster than humans can inspect it.

## HOW

We test the *acceptance evidence*, not merely the code. We represent a human-approved behavioral interpretation, construct plausible counterfactual interpretations, derive minimal cases where they disagree, and ask whether the evidence already trusted by the development process can distinguish them.

## WHAT

A local-first developer tool for material backend business-rule changes that can produce:
- human-approved behavioral contracts;
- explicit interpretation sets;
- decision-critical clarification;
- plausible counterfactual interpretations;
- minimal distinguishing witnesses;
- acceptance-evidence gaps;
- held-out evaluation probes;
- replayable evidence reports.
